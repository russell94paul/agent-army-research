# UI Prototype Research Plan

## Objective

Test whether the Command World provides faster, more accurate organizational understanding than conventional developer-tool interfaces.

## Prototype A — Control Room

Dense tables, trees, alerts, metrics and timelines.

## Prototype B — Graph Operations View

Node/edge representation with inspectors and replay.

## Prototype C — Command World

Stable spatial world using semantic zoom, formations, routes and fields.

## Test tasks

Participants must:

1. identify the current mission blocker;
2. explain why a validator spawned;
3. detect duplicated work;
4. find stale/contested knowledge;
5. locate unverified output;
6. identify capability/readiness bottleneck;
7. explain why an agent edited an artifact;
8. recover the causal path for a failed verification.

## Measures

```text
time to correct answer
error rate
navigation actions
confidence
NASA-TLX or similar cognitive-load measure
retention after short delay
```

## Conditions

Test:
- novice operators,
- experienced developers,
- high event density,
- low event density.

## Decision rule

Do not choose Command World merely because users prefer its aesthetics.

Spatial UI wins only where it measurably improves operator tasks or reduces cognitive burden.

Hybrid UI is an acceptable outcome.
