# R20 — Product Thesis: Agent Army as an Artificial Organization Engineering Platform

## Objective

Determine what Agent Army should become.

Is it:

- an agent dashboard,
- an agent team builder,
- a workflow orchestrator,
- a developer operations console,
- or a new category: an Artificial Organization Engineering Platform?

## Central hypothesis

The primary programmable object may become:

```text
Organization
```

rather than only:

```text
prompt
workflow
agent
```

An organization contains:

```text
missions
agents
teams
capabilities
knowledge
skills
policies
topology
communication
resources
evidence
history
governance
learning
```

## Research questions

1. What existing fields already cover this idea?
2. What is genuinely new when LLM agents, knowledge systems, organizational digital twins and simulation are combined?
3. Who is the buyer/user?
4. What jobs-to-be-done does this solve?
5. What becomes first-class that current agent frameworks treat as incidental?
6. Is "Artificial Organization Engineering" a coherent category?
7. What is the smallest product wedge?

## Compare against

- IDEs,
- workflow engines,
- agent frameworks,
- process mining tools,
- observability tools,
- digital twin systems,
- orchestration frameworks,
- AI operating systems,
- knowledge management tools.

## Required output

Produce:

- category definition,

- what not to build,

End with:

> If Agent Army succeeds, what new object will developers believe is obvious in retrospect?
