# R35 — Laws of Artificial Organizations

## Objective

Attempt to derive a small set of falsifiable engineering laws for systems composed of persistent AI agents, teams, shared knowledge and adaptive organizational structures.

Do not create a manifesto of attractive slogans.

A useful law should:

- describe a recurring constraint,
- predict a tradeoff or failure,
- generalize across multiple agent implementations,
- be testable,
- change architecture or operational behavior.

## Starting hypotheses to attack

```text
Intent before topology.
Evidence before autonomy.
Knowledge without provenance is rumor.
Context is logistics.
Capability is earned.
Local autonomy requires global boundaries.
Organizational state must be observable before self-modification.
Doctrine changes slower than strategy.
Simulation precedes evolution.
Activity is not progress.
Shared understanding is a runtime asset.
Organizational structure has a coordination cost.
```

## Research analogues

Search for underlying principles in:

- distributed systems,
- control theory,
- cybernetics,
- safety engineering,
- organizational design,
- military mission command,
- economics,
- swarm intelligence,
- software engineering,
- reliability engineering.

## Law format

For each proposed law provide:

```text
LAW
PRECISE CLAIM
MECHANISM
PRIOR ART
COUNTEREXAMPLE
BOUNDARY CONDITIONS
FAILURE MODE PREVENTED
MEASUREMENT
FALSIFICATION TEST
DESIGN IMPLICATION
EVIDENCE TIER
```

## Required challenge

For every starting law, actively search for a case where following it would make the system worse.

Examples:

- could intent-first design slow trivial work?
- can low-risk autonomy precede formal evidence?
- can useful heuristic knowledge exist without provenance?
- can live adaptation ever precede high-fidelity simulation?

Refine scope accordingly.

## Required output

1. at least 20 candidate laws;
2. rejected laws and reasons;
3. final minimal set of at most 12;
4. test plan;
5. architecture implications;
6. operational checklist.

Finish with:

> Which laws are strong enough that violating them should trigger an architecture review in Agent Army?
