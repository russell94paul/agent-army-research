# R43 — Knowledge, Skills, Capabilities and Organizational Expertise

## Objective

Design a persistent capability system where useful organizational learning can compound across missions without becoming an untrusted memory pile.

## Required distinctions

Define and test:

```text
Observation
Claim
Evidence
Knowledge
Experience
Lesson
Skill
Procedure
Capability
Expertise
Doctrine
```

## Skill registry

A skill may require:

```text
ID
version
inputs
outputs
tool requirements
permissions
tests
compatibility
known failure modes
performance history
status
```

Research how skills should be discovered, selected, composed, deprecated and promoted.

## Capability

A role label is not capability.

Design an evidence-backed capability representation based on historical outcomes.

Study:

- contextual competence,
- sample size,
- recency,
- task similarity,
- confidence intervals,
- failure history.

Avoid universal scalar ratings where multidimensional competence is required.

## Expertise

Investigate whether expertise should be:

- agent-owned,
- team-owned,
- organization-owned,
- skill-derived,
- or dynamically inferred.

## Knowledge/skill economy

Explore whether the organization benefits from mechanisms for:

- publishing reusable findings,
- measuring reuse,
- identifying high-value skills,
- prioritizing curation,
- routing to demonstrated expertise.

Do not assume literal financial rewards.

## Lifecycle

Design:

```text
experience
→ lesson
→ knowledge candidate
→ validated knowledge
→ reusable procedure
→ tested skill
→ demonstrated capability
→ possible doctrine
```

Identify where automation should stop for human/governance review.

## Required output

1. canonical object distinctions;
2. knowledge lifecycle;
3. skill registry;
4. capability graph;
5. expertise/routing model;
6. promotion/deprecation rules;
7. metrics;
8. UI/inspectors;
9. security/provenance requirements;
10. implementation sequence.

Finish with:

> Which persistent learning objects provide the highest compounding value without creating an epistemic governance problem?
