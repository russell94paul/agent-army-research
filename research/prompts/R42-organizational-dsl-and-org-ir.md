# R42 — Organizational DSL and Org-IR

## Objective

Determine whether artificial organizations need a declarative source language, a normalized intermediate representation, or both.

Avoid inventing a DSL merely because the compiler metaphor is attractive.

## Candidate pipeline

```text
Human mission/config
        ↓
Organization DSL / structured source
        ↓
validation / normalization
        ↓
Org-IR
        ↓
compiler passes
        ↓
Executable Organization Plan
        ↓
runtime state
```

## Questions

1. What is authored by humans?
2. What is generated by a planner/compiler?
3. What changes only at runtime?
4. How are dynamic topology rules represented?
5. How are policies and authority represented?
6. How are capability requirements expressed?
7. Can static checks detect impossible missions?
8. Can organization versions be diffed meaningfully?

## Compare prior systems

Study:

- Kubernetes manifests,
- Terraform,
- BPMN,
- DAG/workflow DSLs,
- PDDL/planning languages,
- policy languages,
- actor configuration,
- infrastructure-as-code,
- compiler IR design.

## Candidate source example

```yaml
mission:
  intent:
  end_state:
  invariants:

capabilities:
  required:

organization:
  constraints:
  topology_policy:

resources:
  budget:

verification:
  assertions:
```

Determine which fields are premature.

## Org-IR requirements

Org-IR should be:

- normalized,
- versioned,
- machine-validatable,
- diffable,
- explainable,
- independent enough from UI.

Potential sections:

```text
intent
capability plan
role assignments
topology
resource allocation
context plan
communication policy
verification graph
governance constraints
```

## Compiler diagnostics

Research diagnostics like:

```text
missing capability
impossible permission
budget infeasible
unverifiable end state
cyclic dependency
validator unavailable
```

## Required output

Produce:

1. argument for/against a DSL;
2. source/schema proposal;
3. Org-IR proposal;
4. compiler passes;
5. static checks;
6. versioning/migrations;
7. organization diff;
8. examples;
9. runtime boundary;
10. MVP recommendation.

Finish with:

> Is an artificial organization best represented as configuration, a program, a graph, a policy bundle, or a hybrid?
